## 경계 사례와 시연 데이터

`samples/posts.json`의 각 예제가 Mock API 테스트와 브라우저 테스트를 모두 통과했다.

- 급여 마감 중단: Level 1
- 팀 내 결재 승인 장애: Level 2
- 다시 입력하면 조회 가능한 검색 문제: Level 3
- 급여 명세서 조회 문의: Level 4
- 전 직원 필수 업무 기능 중단: Level 1
- 정상 업무 중 UI 색상 개선 요청: Level 4
- 제목에 긴급이 있지만 도움말 위치 문의: Level 4
- 오류라는 단어 없이 급여 지급 업무 중단: Level 1
- 대상자가 전체 임직원인 단순 공지 요청: Level 4
- 짧고 모호한 내용: Level 3 / 신뢰도 0.35 / 추가 확인 안내
- 한글·영문·숫자·특수문자 혼합 및 우회 가능: Level 3
- 여러 팀의 주요 기능 장애: Level 2

Mock은 예제의 세 입력 필드를 비교하는 fixture 재생이다. 임의 문장의 의미를 분석하지 않는다. 예제 외 입력은 낮은 신뢰도 결과를 반환하고 화면에 시연임을 안내한다. 이 테스트 결과를 실제 Jev 모델의 분류 정확도로 해석하면 안 된다.

## 범위·보안 검토

- 배포 관리·알림 전송·게시글 수정/삭제·영속 DB·로그인·카테고리 분류·담당자 배정·관리자 화면·통계 대시보드 없음.
- 질의 목록은 현재 React 메모리에만 유지하며 localStorage/sessionStorage를 사용하지 않음. 새로고침·탭 종료 시 초기화됨.
- 키는 서버 환경에서만 읽고 public config에 포함하지 않음. 설정 객체 repr에서도 숨김.
- SDK request/response body logging 비활성화. 오류 메시지에 외부 응답 상세·원문·키를 전달하지 않음. 테스트에서 원문·키 로그 누출을 검사.
- 사용자가 생성한 실제 `.env`는 Git 제외 상태이며, 저장소에는 `.env.example`만 포함.
- Jev 공식 endpoint를 명시하여 SDK base URL 환경 설정에 의해 의도치 않은 주소로 전송되지 않게 함.
- 서버 요청 전체 제한 20초, 브라우저 분석 제한 30초. 제출 중 입력과 버튼 비활성화, ref로 재진입 차단.

향후 알림 기능의 확장 지점은 내부 `PriorityAnalysis` 모델이다. 확률·신뢰도·signals를 보존하므로 별도 정책 계층을 연결할 수 있다. 현재 알림 판단 정책이나 전송은 구현하지 않았다.

## 질의 상세 복구와 운영 규칙 진단

2026-09-24의 `0846373` revert가 읽기 전용 질의 상세 컴포넌트와 제목 클릭 동작을 제거한 것을 확인하고 현재 운영 규칙 UI와 병합해 복구했다. 기획서 조건 20은 **통과**: 목록에서 상세 열기·돌아가기, 원래 긴급도와 처리 우선순위·규칙 사유, 정렬 및 작성 중 입력 유지, 상세 열람 시 API 재호출 없음이 프론트엔드 테스트와 브라우저 테스트에서 확인됐다.

복구 후 최종 검증: 프론트엔드 Vitest **24개 통과**, TypeScript 타입 검사 **통과**, Vite 빌드 **통과**, Playwright Chromium **3개 통과**. 백엔드 코드는 이번 복구 작업에서 변경하지 않았으며 앞선 운영 규칙 구현의 pytest **78개 통과** 결과를 유지한다.

운영 규칙의 주제 설명을 명령문처럼 입력하면 관련성 확률이 낮아질 수 있다. 개인정보 없는 합성 질의로 실제 Jev 모드에서 사용자 예시의 문장형 설명은 관련성 0.68·원래/처리 Level 4, 간결한 주제 설명은 관련성 0.96·원래 Level 4/처리 Level 1을 받았다. 이는 해당 합성 질의의 관찰 결과이며 실제 사용자 질의의 관련성 확률을 뜻하지 않는다. 목록은 규칙 적용 여부와 관련성 확률, 80% 미달 사유를 표시한다. 목록의 긴급도 신뢰도는 규칙 관련성 및 정답률과 구별해 안내한다.
